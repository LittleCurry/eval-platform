# 同事试用指引（M7-7）

> 这份文档是给**试用的人**看的，不是给你看的。目标是：一个没听过这个项目的同事，
> 在 20 分钟内自己走完「看报告 → 定位 → 标 case → 看闭环」，并且**能说出哪一步让他困惑**。
>
> 你（项目负责人）要做的事只有三件：给地址 + 给账号、念一遍"你可以随便用，只读也行"、
> 试用结束后把下面的反馈表填掉。

---

## 一、给试用者的开场（30 秒，照着念）

> 这是一个 RAG 评测平台，用来回答"我的 RAG 改完到底变好了没有、坏在哪一题"。
> 页面右上角是你的账号，菜单里左边几个是"看结果"的，中间是"跑实验"的。
> 你的账号是**只读**（或编辑者，按实际情况说）：看报告、看对比、看标注结果都没问题，
> 想改数据或提任务需要编辑者/管理员权限 —— 想试写操作就告诉我，我给你开。
>
> 请你**故意按你自己的习惯点**，不要客气，卡住的地方就是我要改的地方。
> 我不会在旁边提示，除非你问。

## 二、试用路径（20 分钟，让他自己走）

| 步骤 | 让他做什么 | 观察什么（你记，别说话） |
|------|-----------|------------------------|
| 1 | 打开 `http://<部署地址>/`，登录 | 找得到登录入口吗？ |
| 2 | 在「评测运行」里找一条**具体**的 run，说出它用的 top-k 和配置指纹 | 他知道"配置指纹"是什么吗？会不会去找 |
| 3 | 打开某条 run 的报告，说出"这次评测有没有幻觉" | 报告页第一屏给答案了吗？"没有判定"和"零幻觉"分得清吗 |
| 4 | 在"最差用例"里挑一题，点「详情」，说出这题**为什么**差 | 主因、断言、检索上下文三块他都看了吗 |
| 5 | 去「A/B 对比」比两条 run，说出"这次改动值不值" | 他会不会自己看 p 值和"修好/变坏" |
| 6 | 去「标注」给一题打归因 + 改状态（只读账号改成：**说出**他会怎么点） | 快捷键提示看得见吗？状态机限制让他困惑吗 |
| 7 | 去「闭环」看那几条标注现在什么状态 | "improved / 未验证"他理解成什么 |
| 8 | 回到首页/报告，回答："如果明天要再跑一次，你会怎么跑？" | 他找得到"改配置重跑"或"配置模板"吗 |

> 只读账号也能走完 1–5、7；第 6 步让他口头描述。**不要为了走完流程给他管理员权限** ——
> 我们要的信息里有一半来自"权限被挡住时，界面有没有告诉他为什么"。

## 三、反馈表（填 3–5 条就够了，宁少勿滥）

每条都要**具体到页面 + 他当时想干什么 + 发生了什么**。含糊的"挺好用的"没有价值。

| # | 类型 | 页面/入口 | 他做了什么 | 他期待什么 | 实际发生 | 我的判断（高/中/低） | 处理 |
|---|------|----------|-----------|-----------|---------|--------------------|------|
| 1 | 找不到 / 看不懂 / 不信 / 多余 / 慢 / bug |  |  |  |  |  |  |
| 2 |  |  |  |  |  |  |  |
| 3 |  |  |  |  |  |  |  |

**类型怎么选**（这六个词能覆盖绝大多数反馈，也直接决定我改哪里）：

- **找不到**：知道要做这件事，但在界面上找不到入口 → 改导航 / 改文案 / 改空态引导。
- **看不懂**：找到了但不知道这个数字/标签是什么意思 → 改表头提示 / 改口径说明。
- **不信**：看懂了但不相信这个结论（"凭什么说修好了"）→ 补证据链（那正是闭环页要解决的）。
- **多余**：界面上有他永远不看的东西 → 收起来或删掉。
- **慢**：等待时间说不清楚（不知道是在跑还是卡住了）→ 补进度/心跳/预计时间。
- **bug**：明确的功能错误 → 直接进 issue，写完用例再修。

## 四、试用结束后（你自己做，10 分钟）

1. 把上面的表填完，**当天**发给试用者确认一句："我理解得对吗？"（避免我理解偏了）。
2. 按下面规则定优先级，只修**高优**项：
   - 高：挡住主流程（建项目→导入→跑评测→看报告→标 case 任一步走不通），或让人**误解结论**。
   - 中：需要绕路但能自己解决；或每次都要重复问同一件事。
   - 低：审美偏好、极少数场景。
3. 修完的高优项写进 `process.md` 的 **M7-7 小结**（含"原来什么样 / 现在什么样 / 怎么验证的"），
   并补一条测试或一条 UI 断言 —— 反馈修完不能再退回去。
4. 试用者提了但不打算做的，写进 `README.md` 的「已知限制」，并写清**为什么不做**。

## 五、我这边已经准备好的东西（让试用不依赖你的手工操作）

- `make deploy-up`：全栈一键起（迁移 → api → worker → web），浏览器开 `WEB_PORT` 即可。
- 账号：管理员在 `/users` 页面加人即可（默认给「只读」，让他先只读试一轮）。
- `scripts/demo.sh`：演示路径（不花 token）。**你自己先跑一遍**，确认环境没问题再叫同事。
- `make regress`：交付前体检（不花 token）。改完反馈后先跑它。
- `docs/deploy.md`：备份/升级/排障。同事试用期间别在同一个库上跑 `make worker` 常驻进程，
  除非你确认队列里没有你要演示的任务（见 process.md 里"队列 live 测试误伤真实任务"的坑）。
