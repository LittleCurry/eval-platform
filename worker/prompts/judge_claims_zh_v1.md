# 任务
把【答案】拆成原子断言（claim），并逐条对照【资料】判定。

# 什么是原子断言
- 一句话只表达一个可判真伪的事实：数字、期限、枚举值、状态、权限、流程步骤、字段名等；
- 去掉无信息量的套话（"根据资料""综上所述""需要注意的是"），也不要寒暄；
- 保留原文的关键限定词（如"默认""最多""仅""必须""可配范围"），不要改写数字与术语；
- 同一事实只出现一次；【答案】里的举例若只是复述资料，不额外计一条。

# 判定标签（三条里选一条）
- supported：【资料】明确支持该断言（数字、期限、枚举与资料完全一致）。
- unsupported：【资料】与该断言矛盾，**或者【资料】完全没有提到该断言的内容而答案却把它当作事实陈述**。
  · 例：资料只说"站内通知"，答案说"会通过企业微信通知" → unsupported（资料没提企微渠道）。
  · 例：资料说"默认 7 天"，答案说"默认 30 天" → unsupported（与资料矛盾）。
- irrelevant：该断言与【问题】无关（答非所问、跑题、泛泛而谈），既非被支持也非被反驳。
  · 例：问的是"线索回收天数"，答案里却在讲"套餐价格" → irrelevant。

# 证据要求
- supported：evidence 必须是【资料】中的**原文片段**（原样摘抄，不要改写、不要翻译）；
- unsupported：若资料里有矛盾证据，evidence 给该原文片段；若资料完全没提，evidence 写空字符串；
- irrelevant：evidence 写空字符串。
- reason 用一句中文说明判定理由（不超过 30 字）。

# 输出格式（只输出 JSON，前后不要任何解释、不要 markdown 代码块）
{"claims":[{"id":1,"text":"...","label":"supported","evidence":"...","reason":"..."}]}
- id 从 1 开始按【答案】出现顺序连续编号；
- 若【答案】没有任何可核查的断言（例如只说了"资料中未提及"），输出 {"claims":[]} ；
- 不要输出 label 之外的取值，不要输出注释。
